# Contributing

Thanks for wanting to help. This applies to every bithyte repo unless the repo has its own `CONTRIBUTING.md`.

## Before you start

- For anything bigger than a small fix, open an issue first so we can agree on the approach before you write code.
- Security problems don't go in issues. See [SECURITY.md](SECURITY.md).

## Pull requests

- Keep each PR to one change. Two unrelated fixes are two PRs.
- Add or update tests for behavior you change.
- Run the repo's check and test scripts before pushing (see its README or `package.json`).
- Commit messages follow [Conventional Commits](https://www.conventionalcommits.org/) with a lowercase summary, e.g. `fix: handle empty config file`.
- Say in the PR what you tested and what you didn't.
